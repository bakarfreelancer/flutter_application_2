1. How Location Works on Mobile

A mobile device can determine its position using three different systems. The OS combines all available sources automatically:

┌─────────────────────────────────────────────────────────┐ │ HOW THE DEVICE FINDS ITS POSITION │ ├──────────────────┬──────────────────┬───────────────────┤ │ GPS │ WiFi / Cell │ Fused API │ ├──────────────────┼──────────────────┼───────────────────┤ │ Satellite signal │ Router + tower │ OS combines all │ │ Outdoor only │ Indoor works │ best of both │ │ ~3 m accuracy │ ~50–200 m │ Dynamic trade-off │ │ High battery │ Low battery │ Balanced │ └──────────────────┴──────────────────┴───────────────────┘ Your app asks the OS → OS returns the best available fix

Coarse Location

Uses WiFi and cell towers. Accuracy ~50–200 m. Lower battery use. Good for showing a city-level map.

Fine Location

Uses GPS chip. Accuracy ~3–10 m. Higher battery use. Required for navigation or pin-drop accuracy.

2. Location Permissions

Location is sensitive data. The OS requires your app to declare the permission in its config file and ask the user at runtime.

Android — AndroidManifest.xml

<!-- Both permissions must be listed -->
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
Declaring the permission in the manifest is only step 1. You must still request it at runtime with Geolocator.requestPermission(). Without the runtime request the permission is never granted, even if it is in the manifest.

Permission States (LocationPermission enum)

StateMeaningWhat to do
deniedNot asked yet or tapped Deny onceCall requestPermission()
whileInUseGranted while the app is openProceed ✅
alwaysGranted even in backgroundProceed ✅
deniedForeverUser tapped "Don't ask again"Open app settings

4. Getting the Device Location (Step by Step)

There are four steps every location-based app must follow:

Step 1: Is GPS hardware enabled on the device? └─ No → show "Please enable GPS" message └─ Yes ↓ Step 2: Do we already have permission? └─ denied → Step 3 └─ granted → Step 4 └─ deniedForever → show "Go to Settings" message Step 3: Ask the user (dialog pops up) └─ Denied again → show error └─ Granted → Step 4 Step 4: Call getCurrentPosition() └─ Returns Position(latitude, longitude, accuracy, …)

Code — complete location loading function

Future<void> _loadLocation() async {
  // Step 1 — is the GPS hardware turned on?
  final serviceEnabled = await Geolocator.isLocationServiceEnabled();
  if (!serviceEnabled) {
    setState(() => _error = 'GPS is disabled. Enable it in device settings.');
    return;
  }

  // Step 2 — check current permission status
  LocationPermission permission = await Geolocator.checkPermission();

  // Step 3 — ask if not granted yet
  if (permission == LocationPermission.denied) {
    permission = await Geolocator.requestPermission();
    if (permission == LocationPermission.denied) {
      setState(() => _error = 'Permission denied.');
      return;
    }
  }

  if (permission == LocationPermission.deniedForever) {
    setState(() => _error = 'Permission permanently denied. Go to App Settings.');
    return;
  }

  // Step 4 — actually read the GPS coordinates
  final position = await Geolocator.getCurrentPosition(
    locationSettings: const LocationSettings(
      accuracy: LocationAccuracy.high,  // GPS chip
    ),
  );

  setState(() => _position = position);
  // position.latitude, position.longitude, position.accuracy
}

5. Showing the Map with flutter_map

Core Concepts

ConceptWhat it does
FlutterMapThe main map widget. Takes MapOptions and a list of layers.
MapOptionsSets the initial center coordinate and zoom level.
TileLayerDownloads and displays map image tiles from a tile server.
MarkerLayerPlaces interactive widgets (pins) at specific coordinates.
LatLngA coordinate: LatLng(latitude, longitude).

Zoom Levels

ZoomWhat you see
3–5Continent level
8–10City level
13–15Neighbourhood level ← our app uses 14
17–18Street / building level

Code — FlutterMap widget

FlutterMap(
  options: MapOptions(
    initialCenter: LatLng(userLat, userLng),
    initialZoom: 14,
  ),
  children: [
    // Layer 1 — the map tiles (OpenStreetMap)
    TileLayer(
      urlTemplate: 'https://tile.openstreetmap.org/{z}/{x}/{y}.png',
      userAgentPackageName: 'com.example.myapp',
    ),

    // Layer 2 — markers drawn on top of the tiles
    MarkerLayer(
      markers: [
        Marker(
          point: LatLng(userLat, userLng),
          width: 48,
          height: 48,
          child: const Icon(Icons.my_location, color: Colors.blue, size: 40),
        ),
      ],
    ),
  ],
)
Layers are drawn in order. Always put TileLayer first (the base map), then MarkerLayer on top. Otherwise pins will be hidden under the map tiles.

6. Full MapScreen Walkthrough

The screen has three possible states — just like our product list screen had loading / error / data states. This is a recurring Flutter pattern.

MapScreen states ───────────────────────────────────────────────────────── _isLoading == true → CircularProgressIndicator _errorMessage != null → Error card + "Try Again" button _position != null → FlutterMap with markers
class _MapScreenState extends State<MapScreen> {
  Position? _position;        // null while loading
  bool _isLoading = true;
  String? _errorMessage;
  List<_Store> _stores = [];  // fake nearby stores

  @override
  void initState() {
    super.initState();
    _loadLocation();  // start the permission + GPS flow on screen open
  }

  @override
  Widget build(BuildContext context) {
    if (_isLoading)        return _loadingWidget();
    if (_errorMessage != null) return _errorWidget();
    return _mapWidget();  // show map only when we have coordinates
  }
}

7. Placing Multiple Markers

We can show as many markers as we want. The spread operator (...) converts a list of stores into individual Marker objects inline. 

// A simple data class for a store
class _Store {
  final String name;
  final LatLng location;
  const _Store(this.name, this.location);
}

// Building fake store positions relative to user
final lat = position.latitude;
final lng = position.longitude;
final stores = [
  _Store('Store A', LatLng(lat + 0.003, lng + 0.004)),
  _Store('Store B', LatLng(lat - 0.005, lng + 0.002)),
  _Store('Store C', LatLng(lat + 0.001, lng - 0.006)),
];

// Inside MarkerLayer, spread the store list into markers
MarkerLayer(
  markers: [
    userMarker,        // user location pin
    ...stores.map((s) => Marker(
      point: s.location,
      child: GestureDetector(
        // Tap a store pin to see its name
        onTap: () => showSnackBar(s.name),
        child: const Icon(Icons.store, color: Colors.red),
      ),
    )),
  ],
)

9. Common Mistakes

MistakeFix
Only adding permission in manifest, not requesting at runtimeAlways call requestPermission() — the manifest alone is not enough
Not checking isLocationServiceEnabled() firstGPS may be off even if permission is granted
Calling getCurrentPosition() without awaitAlways await it — it returns a Future
Putting MarkerLayer before TileLayerLayers paint in order — tiles must be first
Forgetting userAgentPackageName in TileLayerOpenStreetMap requires this to identify your app; without it tiles may be blocked
Using LocationAccuracy.high all the timeUse LocationAccuracy.low for non-navigation use cases — saves battery
