Lecture 06  –  Navigation with Bottom Nav Bar

Topics: IndexedStack  ·  Navigation shell  ·  Dynamic AppBar title  ·  Tab screens

Learning Objectives

  1. Understand the difference between navigation and tab switching.
  2. Use IndexedStack to switch between tab screens.
  3. Build a navigation shell screen that wraps all tabs.
  4. Change the AppBar title automatically based on the active tab.
  5. Create simple, separate screens for each tab.

1. Two Types of Navigation in Flutter

TypeHow it worksExample
Stack navigation Push a new screen on top, pop to go back Tap a product → open Product Detail
Tab navigation Switch between sibling screens — no "back" Tap Home / Search / Cart / Profile in nav bar

In the previous lecture we learned stack navigation (Navigator.push). This lecture is about tab navigation using the BottomNavBar component we already built.

2. The Navigation Shell Pattern

Instead of every screen managing its own AppBar and BottomNavBar, we create one shell screen that holds:

  • The AppBar (title changes per tab)
  • The body — shows whichever tab screen is active
  • The BottomNavBar
┌─────────────────────────────────────────┐
│ TopHeader — title changes per tab │ ← AppBar
├─────────────────────────────────────────┤
│ │
│ HomeContent / SearchScreen / │ ← body (IndexedStack)
│ CartScreen / ProfileScreen │
│ │
├─────────────────────────────────────────┤
│ 🏠 Home 🔍 Search 🛒 Cart 👤 Profile │ ← BottomNavBar
└─────────────────────────────────────────┘
All of this is ONE Scaffold inside MyApp (the shell)

4. The Simple Tab Screens

Each tab screen is just a StatelessWidget that returns a Center with a Text. No Scaffold, no AppBar — those are handled by the shell.

lib/screens/search_screen.dart 
import 'package:flutter/material.dart';

class SearchScreen extends StatelessWidget {
  const SearchScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return const Center(
      child: Text('Search Screen', style: TextStyle(fontSize: 24)),
    );
  }
}

cart_screen.dart and profile.dart follow the same pattern — just change the class name and text.

5. The Navigation Shell — home.dart

This is the most important file. It does three things:

  1. Holds a list of titles — one per tab
  2. Holds a list of screens — one per tab
  3. Uses IndexedStack to show the active screen
lib/screens/home.dart 
import 'package:flutter/material.dart';
import 'package:flutter_application_2/components/bottom_nav_bar.dart';
import 'package:flutter_application_2/components/top_header.dart';
import 'package:flutter_application_2/screens/cart_screen.dart';
import 'package:flutter_application_2/screens/profile.dart';
import 'package:flutter_application_2/screens/search_screen.dart';

class MyApp extends StatefulWidget {
  const MyApp({super.key});

  @override
  State<MyApp> createState() => _MyAppState();
}

class _MyAppState extends State<MyApp> {

  int _currentIndex = 0; // active tab index

  // One title per tab — index must match BottomNavBar items
  final List<String> _titles = ['Home', 'Search', 'Cart', 'Profile'];

  // One screen per tab
  final List<Widget> _screens = [
    const _HomeContent(),
    const SearchScreen(),
    const CartScreen(),
    const ProfileScreen(),
  ];

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(

        // Title updates automatically: _titles[0]='Home', _titles[1]='Search' ...
        appBar: TopHeader(title: _titles[_currentIndex]),

        // IndexedStack: shows only the child at 'index'
        // All children stay alive in memory (no rebuild on tab switch)
        body: IndexedStack(
          index: _currentIndex,
          children: _screens,
        ),

        bottomNavigationBar: BottomNavBar(
          currentIndex: _currentIndex,
          onTap: (index) {
            setState(() {
              _currentIndex = index;
            });
          },
        ),
      ),
    );
  }
}

6. IndexedStack — Deep Dive

What is IndexedStack?

IndexedStack is a Flutter widget that takes a list of children and an index number. It shows only the child at that index position, and hides all the others — but it does not destroy them. Think of it like a stack of papers on a desk: only the top paper is visible, but all the others are still there underneath.

Basic Syntax

IndexedStack(
  index: 2,             // show child at position 2 (CartScreen)
  children: [
    HomeContent(),    // index 0 — hidden
    SearchScreen(),   // index 1 — hidden
    CartScreen(),     // index 2 — VISIBLE
    ProfileScreen(),  // index 3 — hidden
  ],
)

How it looks internally

index = 2 → CartScreen is on top (visible)

┌─────────────────────────────────┐
│ CartScreen ← VISIBLE │
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
│ SearchScreen ← hidden │
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
│ HomeContent ← hidden │
└─────────────────────────────────┘
All screens exist in memory — only visibility changes

Which screen shows at which index?

_currentIndexVisible screenAppBar title
0_HomeContentHome
1SearchScreenSearch
2CartScreenCart
3ProfileScreenProfile

Why IndexedStack and not if/else?

You could use an if/else to swap screens, but every tab switch would destroy and recreate the screen widget. This means:

  • Any text typed in a form gets wiped when you switch tabs
  • A video resets to the beginning
  • A scroll position jumps back to the top

With IndexedStack, the screens are kept alive in memory. Switch from Home to Search and back — the form still has your typed text. 

// ❌ if/else — screen is destroyed and rebuilt every time you switch tabs
body: _currentIndex == 0 ? HomeContent() : SearchScreen(),

// ✅ IndexedStack — screen stays alive, only visibility changes
body: IndexedStack(
  index: _currentIndex,
  children: [HomeContent(), SearchScreen(), ...],
),
IndexedStack vs Navigator.push:
Navigator.push — stacks a new screen on top. User can press the back button to return.
IndexedStack — swaps between sibling screens. There is no back button between tabs. Use Navigator.push for detail screens; use IndexedStack for tab navigation.
