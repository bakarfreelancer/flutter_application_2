1. What Is Authentication?

Authentication = proving you are who you claim to be.

In most apps the process works like this:

  1. User enters email + password and taps Login
  2. The app sends that data to the server
  3. The server checks the credentials and responds with a token
  4. The app saves that token and sends it with future requests to prove identity
  5. When the user logs out, the token is deleted
User taps Login
↓
App sends email + password → Server
↓
Server responds with a Token (e.g. "QpwL5tpe83ilfN2")
↓
App saves token to SharedPreferences
↓
Next time app opens → token found → user is still logged in ✅
What is a Token? Think of it like a ticket at an event. Once you show your ID at the door (login), you get a ticket (token). You show the ticket to get in — you don't need to show your ID again every time.

2. The Test API — reqres.in

We will use reqres.in — a free, public fake API designed for learning. It behaves exactly like a real authentication server but requires no setup.

Action URL Method Test Email Test Password
Login https://reqres.in/api/login POST eve.holt@reqres.in cityslicka
Register https://reqres.in/api/register POST eve.holt@reqres.in pistol

A successful login response looks like:

{
  "token": "QpwL5tpe83ilfN2"
}

A failed login response looks like:

{
  "error": "user not found"
}
Note: reqres.in only accepts specific email/password combinations listed above. Any other credentials will return an error — this is intentional for the demo. In a real app, your server would accept any valid registered user.

4. Step 1 — Add Auth Methods to UserStorage

We already use UserStorage to save name/contact/address. Now we add 3 more methods to save and clear the auth token.

lib/services/user_storage.dart (new methods only) 
// --- Auth keys ---
static const String _keyToken = 'auth_token';
static const String _keyEmail = 'auth_email';

// Save the auth token and email after a successful login/register
static Future<void> saveToken({
  required String token,
  required String email,
}) async {
  final prefs = await SharedPreferences.getInstance();
  await prefs.setString(_keyToken, token);
  await prefs.setString(_keyEmail, email);
}

// Get the stored token (empty string if not logged in)
static Future<String> getToken() async {
  final prefs = await SharedPreferences.getInstance();
  return prefs.getString(_keyToken) ?? '';
}

// Get the stored email
static Future<String> getEmail() async {
  final prefs = await SharedPreferences.getInstance();
  return prefs.getString(_keyEmail) ?? '';
}

// Remove token and email (used when logging out)
static Future<void> clearAuth() async {
  final prefs = await SharedPreferences.getInstance();
  await prefs.remove(_keyToken);
  await prefs.remove(_keyEmail);
}

5. Step 2 — Create AuthService

AuthService is responsible for making the HTTP calls. It returns a simple Map so the screen can check if the call succeeded.

lib/services/auth_service.dart 
import 'dart:convert';
import 'package:http/http.dart' as http;

class AuthService {
  static const String _baseUrl = 'https://reqres.in/api';

  // Login — returns { 'success': true, 'token': '...' }
  //              or  { 'success': false, 'error': '...' }
  static Future<Map<String, dynamic>> login(
    String email, String password,
  ) async {
    try {
      final response = await http.post(
        Uri.parse('$_baseUrl/login'),
        headers: {'Content-Type': 'application/json'},
        body: jsonEncode({'email': email, 'password': password}),
      );

      final data = jsonDecode(response.body);

      if (response.statusCode == 200) {
        return {'success': true, 'token': data['token']};
      } else {
        return {'success': false, 'error': data['error'] ?? 'Login failed'};
      }
    } catch (e) {
      return {'success': false, 'error': 'Network error. Check your connection.'};
    }
  }

  // Register — same return format as login
  static Future<Map<String, dynamic>> register(
    String email, String password,
  ) async {
    try {
      final response = await http.post(
        Uri.parse('$_baseUrl/register'),
        headers: {'Content-Type': 'application/json'},
        body: jsonEncode({'email': email, 'password': password}),
      );

      final data = jsonDecode(response.body);

      if (response.statusCode == 200) {
        return {'success': true, 'token': data['token']};
      } else {
        return {'success': false, 'error': data['error'] ?? 'Registration failed'};
      }
    } catch (e) {
      return {'success': false, 'error': 'Network error. Check your connection.'};
    }
  }
}
Why wrap in try/catch? If the phone has no internet, http.post() throws an exception instead of returning a response. The catch block handles this gracefully by returning a friendly error message instead of crashing the app.

6. Step 3 — Create AuthProvider

Just like CartProvider manages the cart, AuthProvider manages whether the user is logged in. Any screen that needs to know about auth state can listen to this provider.

lib/providers/auth_provider.dart 
import 'package:flutter/material.dart';
import 'package:flutter_application_2/services/user_storage.dart';

class AuthProvider extends ChangeNotifier {

  bool _isLoggedIn = false;
  String _email = '';
  String _token = '';

  bool get isLoggedIn => _isLoggedIn;
  String get email    => _email;
  String get token    => _token;

  // Called from SplashScreen — checks if a token is already saved
  Future<void> checkAuthStatus() async {
    final token = await UserStorage.getToken();
    final email = await UserStorage.getEmail();
    if (token.isNotEmpty) {
      _token = token;
      _email = email;
      _isLoggedIn = true;
      notifyListeners();
    }
  }

  // Called after a successful login or register API response
  Future<void> login(String email, String token) async {
    await UserStorage.saveToken(token: token, email: email);
    _token = token;
    _email = email;
    _isLoggedIn = true;
    notifyListeners(); // 🔔 tell all listeners: user is now logged in
  }

  // Called from the Profile screen logout button
  Future<void> logout() async {
    await UserStorage.clearAuth();
    _token = '';
    _email = '';
    _isLoggedIn = false;
    notifyListeners(); // 🔔 tell all listeners: user is now logged out
  }
}

7. Step 4 — Register AuthProvider in main.dart

Before Lecture 13, main.dart had a single ChangeNotifierProvider for the cart. Now we need two providers. We switch to MultiProvider.

lib/main.dart 
import 'package:flutter/material.dart';
import 'package:provider/provider.dart';
import 'package:flutter_application_2/providers/cart_provider.dart';
import 'package:flutter_application_2/providers/auth_provider.dart'; // NEW
import 'package:flutter_application_2/screens/splash.dart';

void main() {
  runApp(
    // MultiProvider lets us register MORE THAN ONE provider at once.
    MultiProvider(
      providers: [
        ChangeNotifierProvider(create: (_) => CartProvider()),
        ChangeNotifierProvider(create: (_) => AuthProvider()),  // NEW
      ],
      child: MaterialApp(
        title: 'My App',
        debugShowCheckedModeBanner: false,
        home: const SplashScreen(),
      ),
    ),
  );
}
MultiProvider is just a convenient shorthand for nesting multiple ChangeNotifierProviders inside each other. The result is identical — all providers are available to every widget in the tree.

8. Step 5 — Update SplashScreen

Previously, the splash screen checked for a stored name to decide where to go. Now it checks for a stored auth token and routes to either LoginScreen or HomeScreen.

lib/screens/splash.dart 
import 'package:provider/provider.dart';
import 'package:flutter_application_2/providers/auth_provider.dart';
import 'package:flutter_application_2/screens/login_screen.dart';

// Inside _SplashScreenState:

Future<void> _navigate() async {
  await Future.delayed(const Duration(seconds: 2));
  if (!mounted) return;

  // Ask AuthProvider to check SharedPreferences for a saved token
  await context.read<AuthProvider>().checkAuthStatus();

  if (!mounted) return;

  final isLoggedIn = context.read<AuthProvider>().isLoggedIn;

  Navigator.pushReplacement(
    context,
    MaterialPageRoute(
      builder: (_) => isLoggedIn
          ? const MyApp()        // token found → go to home
          : const LoginScreen(), // no token  → go to login
    ),
  );
}

9. Step 6 — Build the Login Screen

The login screen has an email field, a password field, a Login button, and a link to the Register screen. When the button is tapped, it calls AuthService.login() and on success calls AuthProvider.login() to save the token.

lib/screens/login_screen.dart (key parts) 
class _LoginScreenState extends State<LoginScreen> {
  final _formKey = GlobalKey<FormState>();
  final _emailController    = TextEditingController();
  final _passwordController = TextEditingController();
  bool _isLoading = false;

  Future<void> _login() async {
    // 1. Validate the form
    if (!_formKey.currentState!.validate()) return;

    // 2. Show loading spinner
    setState(() => _isLoading = true);

    // 3. Call the API
    final result = await AuthService.login(
      _emailController.text.trim(),
      _passwordController.text.trim(),
    );

    if (!mounted) return;
    setState(() => _isLoading = false);

    if (result['success'] == true) {
      // 4. Save token via AuthProvider
      final authProvider = context.read<AuthProvider>();
      await authProvider.login(_emailController.text.trim(), result['token']);

      if (!mounted) return;

      // 5. Go to Home — remove all previous routes so user can't go back
      Navigator.pushAndRemoveUntil(
        context,
        MaterialPageRoute(builder: (_) => const MyApp()),
        (route) => false,
      );
    } else {
      // Show error message
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(content: Text(result['error']),
                 backgroundColor: Colors.red),
      );
    }
  }
Why pushAndRemoveUntil? After login we clear the navigation stack. This prevents the user from pressing the Android Back button to go back to the Login screen while they are already in the app.

10. Step 7 — Add Logout to ProfileScreen

The profile screen now shows the user's email (from AuthProvider) and has a Logout button at the bottom.

lib/screens/profile.dart (key parts) 
// Read email from AuthProvider to display in profile
final email = context.watch<AuthProvider>().email;

// Logout method — shows a confirmation dialog first
Future<void> _logout() async {
  final confirmed = await showDialog<bool>(
    context: context,
    builder: (ctx) => AlertDialog(
      title: const Text('Logout'),
      content: const Text('Are you sure you want to logout?'),
      actions: [
        TextButton(
          onPressed: () => Navigator.pop(ctx, false),
          child: const Text('Cancel'),
        ),
        TextButton(
          onPressed: () => Navigator.pop(ctx, true),
          child: const Text('Logout',
              style: TextStyle(color: Colors.red)),
        ),
      ],
    ),
  );

  if (confirmed != true) return; // user cancelled
  if (!mounted) return;

  // Clear token via AuthProvider
  await context.read<AuthProvider>().logout();

  if (!mounted) return;

  // Go to Login, clear all routes
  Navigator.pushAndRemoveUntil(
    context,
    MaterialPageRoute(builder: (_) => const LoginScreen()),
    (route) => false,
  );
}

13. Common Mistakes to Avoid

❌ Using context after async gap

await someAsyncCall();
Navigator.push(context, ...); // ⚠️ risky

If the widget is removed while waiting, context is invalid.

✅ Check mounted first

await someAsyncCall();
if (!mounted) return; // ✅ safe
Navigator.push(context, ...);

Always check mounted before using context after an await.

❌ Wrong Provider placement

// Inside a single screen
ChangeNotifierProvider(
  create: (_) => AuthProvider(),
  ...
)

Other screens cannot access it.

✅ Provider at app root

// In main.dart, above MaterialApp
MultiProvider(
  providers: [
    ChangeNotifierProvider(create: (_) => AuthProvider()),
  ], ...
)

Every screen in the app can access it.
