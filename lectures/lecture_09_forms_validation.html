Lecture 09  –  Forms & Validation

Topics: Form  ·  GlobalKey  ·  TextFormField  ·  validator  ·  validate()  ·  Inline error messages

Learning Objectives

  1. Understand why validation matters and what problems it prevents.
  2. Use the Form widget as a container for form fields.
  3. Use GlobalKey<FormState> to control the form from outside.
  4. Replace TextField with TextFormField and write validator functions.
  5. Trigger validation with validate() on button press.
  6. Understand what inline error messages are and how they appear automatically.

1. Why Validation?

Without validation, a user can submit a form with empty fields or wrong data. This causes crashes, bad data in storage, and poor user experience.

Without ValidationWith Validation
User submits empty name → stored as ""Error shown immediately → user fixes it
Phone number "abc" stored → app breaks laterError: "Enter a valid number"
One generic Snackbar for all problemsEach field shows its own specific error below it

2. The Three Key Pieces

Form widget
  └── key: _formKey  ← connects Form to FormState

GlobalKey<FormState> _formKey
  └── _formKey.currentState!.validate()  ← triggers all validators

TextFormField (inside Form)
  └── validator: (value) { ... return null or error string }
PieceWhat it does
FormA widget that groups all TextFormField widgets together
GlobalKey<FormState>A unique key that lets you call validate() on the form from your button
TextFormFieldLike TextField but supports a validator function
validatorA function that checks the field — returns an error string or null

3. TextField vs TextFormField

❌ Before — TextField (no built-in validation)

TextField(
  controller: _nameController,
  decoration: const InputDecoration(
    hintText: 'Enter name',
    border: OutlineInputBorder(),
  ),
)

// Button: manual check
if (_nameController.text.isEmpty) {
  // show snackbar
}

✅ After — TextFormField (with validator)

TextFormField(
  controller: _nameController,
  decoration: const InputDecoration(
    hintText: 'Enter name',
    border: OutlineInputBorder(),
  ),
  validator: (value) {
    if (value!.isEmpty) {
      return 'Name is required';
    }
    return null; // valid
  },
)
Key difference: TextFormField automatically shows the error string returned by validator as red text below the field. With plain TextField, you have to manage error display yourself.

4. How the validator Function Works

The validator receives the current text value of the field. You check it and either return an error message or null.

validator: (value) {
  // 'value' is what the user typed — it can be null so we check for that too

  if (value == null || value.trim().isEmpty) {
    return 'This field is required'; // ← shown as red error below the field
  }

  if (value.length < 3) {
    return 'Must be at least 3 characters'; // ← another error condition
  }

  return null; // ← null means "no error, field is valid"
}
User types "AB" → taps Save

validate() calls validator("AB")
   → value.length < 3 is true
   → returns "Must be at least 3 characters"

Flutter shows error text below the field in red
validate() returns false → button does nothing

5. GlobalKey — Connecting Button to Form

The form fields are inside a Form widget, but the Save button is not inside a field — it's just a button in the Column. How does the button trigger validation on all fields? Through the GlobalKey. 

// Step 1: create the key in the state class
final GlobalKey<FormState> _formKey = GlobalKey<FormState>();

// Step 2: attach it to the Form widget
Form(
  key: _formKey,
  child: Column( ... )
)

// Step 3: call validate() from the button's onPressed
onPressed: () {
  if (!_formKey.currentState!.validate()) {
    return; // stop here — errors are already shown on screen
  }
  // all fields are valid — proceed
  _saveAndContinue();
}
currentState! — The ! tells Dart "I know this is not null". It is safe here because the Form is always built before the button can be pressed.

6. Full Upgraded UserInfoScreen

lib/screens/user_info_screen.dart 
class _UserInfoScreenState extends State<UserInfoScreen> {

  final GlobalKey<FormState> _formKey = GlobalKey<FormState>();

  final TextEditingController _nameController    = TextEditingController();
  final TextEditingController _contactController = TextEditingController();
  final TextEditingController _addressController  = TextEditingController();

  Future<void> _saveAndContinue() async {
    // validate() runs ALL validators — returns false if any fail
    if (!_formKey.currentState!.validate()) return;

    await UserStorage.saveUser(
      name:    _nameController.text.trim(),
      contact: _contactController.text.trim(),
      address: _addressController.text.trim(),
    );

    if (!mounted) return;
    Navigator.pushReplacement(context,
      MaterialPageRoute(builder: (_) => const MyApp()));
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Form(          // ← wrap fields in Form
        key: _formKey,     // ← attach key
        child: Column(
          children: [

            // Name
            TextFormField(
              controller: _nameController,
              validator: (value) {
                if (value == null || value.trim().isEmpty)
                  return 'Name is required';
                if (value.trim().length < 3)
                  return 'Name must be at least 3 characters';
                return null;
              },
            ),

            // Contact
            TextFormField(
              controller: _contactController,
              keyboardType: TextInputType.phone,
              validator: (value) {
                if (value == null || value.trim().isEmpty)
                  return 'Contact number is required';
                final digits = value.replaceAll(RegExp(r'\D'), '');
                if (digits.length < 10)
                  return 'Enter a valid contact number';
                return null;
              },
            ),

            // Address
            TextFormField(
              controller: _addressController,
              maxLines: 3,
              validator: (value) {
                if (value == null || value.trim().isEmpty)
                  return 'Address is required';
                if (value.trim().length < 10)
                  return 'Please enter a more complete address';
                return null;
              },
            ),

            ElevatedButton(
              onPressed: _saveAndContinue,
              child: const Text('Save & Continue'),
            ),
          ],
        ),
      ),
    );
  }
}

7. Validation Flow — Step by Step

User taps "Save & Continue"
         ↓
_formKey.currentState!.validate() is called
         ↓
Flutter calls validator() on every TextFormField
  ├── Name validator → returns "Name is required" → field shows error in red
  ├── Contact validator → returns null → field is valid ✓
  └── Address validator → returns "Please enter a more complete address"
         ↓
validate() returns false (at least one error)
         ↓
_saveAndContinue() returns early — nothing saved

8. The Contact Number Validator — RegExp

For the contact field we use a Regular Expression (RegExp) to strip out all non-digit characters before counting the length. This allows inputs like 0300-123-4567 or 0300 123 4567. 

final digits = value.replaceAll(RegExp(r'\D'), '');
//                                      ↑ \D means "any non-digit character"
// '0300-123-4567' → replaceAll → '03001234567' (length 11) ✓
// 'abc'           → replaceAll → ''             (length 0)  ✗

if (digits.length < 10) return 'Enter a valid contact number';

9. trim() — Why We Use It

Users sometimes accidentally type spaces before or after their input. trim() removes leading and trailing whitespace so " Ali " becomes "Ali". 

// Without trim — "  " passes the isEmpty check but is useless data
if (value.isEmpty) ...

// With trim — spaces-only input correctly fails the check
if (value.trim().isEmpty) ...
