1. What is a Reusable Component?

In Flutter, every piece of UI is a widget. A component is a widget we write once in its own file and then import and use in as many screens as we want — without rewriting the code.

┌─────────────────────────────────┐
│ TopHeader (component file) │
└──────────┬──────────────────────┘
│ import & use
┌──────────▼──────┐ ┌──────────────────┐
│ home.dart │ │ profile.dart │
└─────────────────┘ └──────────────────┘

Why use components?

  • Write once, use everywhere — a single change fixes all screens at once.
  • Clean files — each screen stays small and easy to read.
  • Customizable — pass different values (like title) to the same component.
Our project structure: All reusable components go inside lib/components/ — this keeps them easy to find and import.

3. TopHeader Component

What does it look like?

┌─────────────────────────────────────────┐
│   ☰          Personal App          🔔   │
└─────────────────────────────────────────┘
Orange background · white icons and text

Three widgets arranged in a Row:

PositionWidgetWidget Used
LeftMenu iconIconButton(Icons.menu)
CenterTitle textText(title) — from parameter
RightNotification iconIconButton(Icons.notifications_outlined)

Key Concept — implements PreferredSizeWidget

Flutter's Scaffold expects its appBar property to know its own height. By writing implements PreferredSizeWidget and adding the preferredSize getter, we tell Scaffold: "this widget is 56px tall".

lib/components/top_header.dart 
import 'package:flutter/material.dart';

// Reusable top header — write once, use in any screen
class TopHeader extends StatelessWidget implements PreferredSizeWidget {

  final String title; // ← parameter: provided by the screen that uses this widget

  const TopHeader({super.key, required this.title});

  // Required by PreferredSizeWidget — Scaffold uses this to know AppBar height
  @override
  Size get preferredSize => const Size.fromHeight(kToolbarHeight);

  @override
  Widget build(BuildContext context) {
    return Container(
      color: Colors.orangeAccent,
      padding: const EdgeInsets.symmetric(horizontal: 8.0),
      child: SafeArea(
        child: Row(
          mainAxisAlignment: MainAxisAlignment.spaceBetween,
          children: [
            // Left icon
            IconButton(
              icon: const Icon(Icons.menu, color: Colors.white),
              onPressed: () {},
            ),

            // Center title — uses the 'title' parameter
            Text(
              title,
              style: const TextStyle(
                color: Colors.white,
                fontSize: 20,
                fontWeight: FontWeight.bold,
              ),
            ),

            // Right icon
            IconButton(
              icon: const Icon(Icons.notifications_outlined, color: Colors.white),
              onPressed: () {},
            ),
          ],
        ),
      ),
    );
  }
}
Notice required this.title: Anyone who uses TopHeader must provide a title string. This is how we make one component work for different screens — TopHeader(title: 'Personal App') on Home, TopHeader(title: 'My Profile') on Profile.

4. BottomNavBar Component

What does it look like?

┌──────────────────────────────────────────────┐
│   🏠 Home   🔍 Search   🛒 Cart   👤 Profile   │
└──────────────────────────────────────────────┘
Active tab = orange · inactive = grey

Two Parameters

ParameterTypePurpose
currentIndexintWhich tab is highlighted (0=Home, 1=Search, 2=Cart, 3=Profile)
onTapvoid Function(int)Called when user taps a tab — the screen decides what to do
lib/components/bottom_nav_bar.dart 
import 'package:flutter/material.dart';

class BottomNavBar extends StatelessWidget {
  final int currentIndex;           // which tab is active
  final void Function(int) onTap; // what to do when tapped

  const BottomNavBar({
    super.key,
    required this.currentIndex,
    required this.onTap,
  });

  @override
  Widget build(BuildContext context) {
    return BottomNavigationBar(
      currentIndex: currentIndex,
      onTap: onTap,
      selectedItemColor:   Colors.orangeAccent, // active tab color
      unselectedItemColor: Colors.grey,
      backgroundColor:     Colors.white,
      type: BottomNavigationBarType.fixed, // always show all labels
      items: const [
        BottomNavigationBarItem(
          icon: Icon(Icons.home_outlined),
          activeIcon: Icon(Icons.home),
          label: 'Home',
        ),
        BottomNavigationBarItem(
          icon: Icon(Icons.search_outlined),
          activeIcon: Icon(Icons.search),
          label: 'Search',
        ),
        BottomNavigationBarItem(
          icon: Icon(Icons.shopping_cart_outlined),
          activeIcon: Icon(Icons.shopping_cart),
          label: 'Cart',
        ),
        BottomNavigationBarItem(
          icon: Icon(Icons.person_outlined),
          activeIcon: Icon(Icons.person),
          label: 'Profile',
        ),
      ],
    );
  }
}
Why is BottomNavBar a StatelessWidget? Because it does not store state — it only receives currentIndex and calls onTap. The screen owns the state. This pattern is called "lifting state up".

5. Using Components in Screens

To use a component we must import it, then place it in the Scaffold. Because we track which tab is active, the screen must be a StatefulWidget.

lib/screens/home.dart — key changes 
// Step 1: import the components
import 'package:flutter_application_2/components/top_header.dart';
import 'package:flutter_application_2/components/bottom_nav_bar.dart';

class _MyAppState extends State<MyApp> {

  int _currentIndex = 0; // Step 2: state variable for active tab

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(

        // Step 3: use TopHeader as appBar, pass a title
        appBar: TopHeader(title: 'Personal App'),

        body: /* ... same as before ... */,

        // Step 4: use BottomNavBar as bottomNavigationBar
        bottomNavigationBar: BottomNavBar(
          currentIndex: _currentIndex,
          onTap: (index) {
            setState(() {
              _currentIndex = index; // rebuild with the tapped tab active
            });
          },
        ),
      ),
    );
  }
}

On profile.dart we do the same — but pass a different title and start with tab 3 active: 

appBar: TopHeader(title: 'My Profile'),  // different title, same component

int _currentIndex = 3;               // Profile tab active by default

6. How Import Works in Dart

Every Dart file is its own library. To use a class from another file you must import it using the package: path. 

// Format:  package:<package_name>/<path from lib/ folder>

import 'package:flutter_application_2/components/top_header.dart';
//              ↑ package name (from pubspec.yaml)  ↑ file path inside lib/
FileImport Statement
lib/components/top_header.dart package:flutter_application_2/components/top_header.dart
lib/components/bottom_nav_bar.dart package:flutter_application_2/components/bottom_nav_bar.dart

7. State Flow — How Tab Selection Works

User taps "Cart" tab
     ↓
onTap(2) is called on BottomNavBar
     ↓
setState(() { _currentIndex = 2; }) runs in _MyAppState
     ↓
Flutter rebuilds the screen
     ↓
BottomNavBar receives currentIndex: 2 → Cart icon turns orange
