1. Overview: iOS vs Android Deployment

iOS deployment is stricter and more complex than Android. Apple controls every step of the process more tightly. Understanding the differences helps avoid surprises.

Android (Google Play)

  • Developer fee: $25 one-time
  • Any computer (Mac, Windows, Linux)
  • Review time: hours to 1–2 days
  • Signing: keystore file (.jks)
  • Upload format: AAB file
  • Sideloading: allowed
  • Test distribution: Internal track

iOS (Apple App Store)

  • Developer fee: $99/year
  • Mac with Xcode only
  • Review time: 1–3 days (can be longer)
  • Signing: certificates + provisioning profiles
  • Upload format: IPA (via Xcode or Transporter)
  • Sideloading: not allowed (except Enterprise)
  • Test distribution: TestFlight
iOS builds require a Mac with Xcode. You cannot build an iOS app on Windows or Linux. If you do not have a Mac, you can use a cloud Mac service (MacStadium, GitHub Actions with macos runner, or Codemagic CI/CD) to build remotely.

2. Prerequisites — Complete Before You Start

Mac with macOS Ventura or later

REQUIRED

iOS builds are only possible on macOS. Xcode requires macOS 13.5+ for the latest version.

Xcode (latest version)

REQUIRED

Download from the Mac App Store (free, ~15 GB).
Run sudo xcode-select --switch /Applications/Xcode.app after installation.

Apple Developer Account

$99 USD / YEAR

Required to submit to the App Store and use TestFlight.
Register at developer.apple.com.
Activation takes 24–48 hours.

Apple ID enrolled in Developer Program

REQUIRED

Sign in to Xcode with the same Apple ID used to pay for the Developer Program. Go to Xcode → Settings → Accounts → add Apple ID.

Bundle Identifier

REQUIRED

Like Android's applicationId: reverse domain notation.
Example: com.yourname.shopapp
Register it at developer.apple.com → Identifiers.

iOS Device or Simulator

REQUIRED for testing

The iOS Simulator is included with Xcode.
For device testing: the device must be registered in your Developer account.

App Store Connect Account

REQUIRED

App Store Connect (appstoreconnect.apple.com) is where you manage listings, screenshots, and submissions. Same login as Developer account.

CocoaPods

REQUIRED for Flutter plugins

Flutter's iOS plugins use CocoaPods.
Install: sudo gem install cocoapods
Then: cd ios && pod install

3. Adding iOS Support to a Flutter Project

Our project was created as Android-only. To add iOS support, run one command. This creates the ios/ folder with all required Xcode project files. 

# Add iOS platform support to an existing Flutter project
flutter create --platforms=ios .

# Install iOS dependencies (CocoaPods)
cd ios
pod install
cd ..
# Verify iOS is available
flutter devices
# Should list: iPhone Simulator or connected iPhone

# Run on iOS Simulator
flutter run -d "iPhone 15"

4. Configuring Info.plist

ios/Runner/Info.plist is the iOS equivalent of AndroidManifest.xml. Every permission your app uses must have a usage description here — a human-readable explanation shown in the iOS permission dialog.

Unlike Android, iOS will crash at runtime if a usage description is missing — there is no manifest permission tag, only these strings. 

<!-- ios/Runner/Info.plist — add inside <dict> -->

<!-- Camera (Lecture 22) -->
<key>NSCameraUsageDescription</key>
<string>We use your camera to let you set a profile photo.</string>

<!-- Photo Library (Lecture 22) -->
<key>NSPhotoLibraryUsageDescription</key>
<string>We use your photo library to let you pick a profile photo.</string>

<!-- Location (Lecture 21) -->
<key>NSLocationWhenInUseUsageDescription</key>
<string>We show nearby stores on the map using your location.</string>
Apple reviewers test every permission your app requests. If the usage description does not clearly explain why the app needs it, the app will be rejected. Write honest, user-friendly descriptions — not "Required for app functionality."

6. Code Signing — The Key Difference from Android

iOS code signing involves three interconnected pieces that must all match. This is the part that confuses most developers coming from Android.

THREE PIECES OF iOS CODE SIGNING ────────────────────────────────────────────────────────────────────── 1. Certificate (.cer) Proves YOU are an Apple-registered developer. Generated in Keychain Access, uploaded to developer.apple.com. Two types: Development (testing) and Distribution (App Store). 2. App ID / Bundle Identifier Registered at developer.apple.com → Identifiers. Ties the app to a specific bundle ID (e.g. com.yourname.shopapp). Enables capabilities (push, CloudKit, etc.) 3. Provisioning Profile (.mobileprovision) Links Certificate + App ID + (optionally) Device IDs together. Four types: • Development → run on registered test devices • Ad Hoc → distribute to up to 100 registered devices • App Store → submit to the App Store • Enterprise → in-house distribution (separate $299/yr program) ALL THREE MUST MATCH for a build to succeed.

Automatic Signing (Recommended for Beginners)

Xcode can manage certificates and provisioning profiles automatically. This is strongly recommended — manual signing is error-prone.

  1. Open ios/Runner.xcworkspace in Xcode
  2. Select Runner → Signing & Capabilities
  3. Check "Automatically manage signing"
  4. Select your team (your Developer account)
  5. Xcode creates and renews certificates and profiles automatically

7. Building for Release

Method A: Flutter CLI (simplest)

# Build an unsigned release archive
flutter build ipa

# Build with specific export method
flutter build ipa --export-method app-store

# Output: build/ios/ipa/flutter_application_2.ipa
flutter build ipa requires an ExportOptions.plist file for distribution signing. For the simplest workflow, build and archive directly in Xcode using Method B below.

Method B: Xcode Archive (most reliable)

  • 1
    Open ios/Runner.xcworkspace in Xcode (not .xcodeproj).
  • 2
    In the device selector at the top, choose Any iOS Device (arm64) — not a simulator.
  • 3
    Menu → Product → Archive. Xcode compiles a release build and opens the Organizer window.
  • 4
    In the Organizer: select your archive → click Distribute App.
  • 5
    Choose distribution method: TestFlight & App Store for submission, or Ad Hoc for device installation.
  • 6
    Xcode signs, validates, and uploads the build to App Store Connect automatically.

8. TestFlight — Beta Testing

TestFlight is Apple's official beta distribution platform. Always use it before submitting to production — it lets you find bugs with real users without going through the full App Store review.

TESTFLIGHT DISTRIBUTION ────────────────────────────────────────────────────────────────────── Internal Testers (up to 100) → Apple Developer team members → Available minutes after upload → No review required External Testers (up to 10,000) → Anyone with an email invitation → Requires a quick Beta App Review (1–2 days) → They install via the TestFlight app
  • 1
    Upload via Xcode Archive (Method B above) or Transporter app.
  • 2
    Go to appstoreconnect.apple.com → your app → TestFlight tab.
  • 3
    Wait for processing (10–30 minutes). Then the build appears under iOS builds.
  • 4
    For internal testers: click the build → enable it for internal testing → add testers by email.
  • 5
    For external testers: click Add External Testers → submit for Beta App Review → share the invite link after approval.

9. App Store Connect — Submission Setup

  • 1
    Create a new app
    App Store Connect → My Apps → + → New App.
    Fill in: platform (iOS), name, primary language, Bundle ID, and SKU (any unique string).
  • 2
    Fill in App Information
    Category, age rating, copyright, support URL, marketing URL, privacy policy URL.
  • 3
    Prepare the store listing
    Promotional text (170 chars), description, keywords (100 chars total), what's new.
  • 4
    Add screenshots
    Required sizes: 6.9" (iPhone 16 Pro Max) and 12.9" (iPad Pro) are the most common. You can take screenshots in the simulator using File → Take Screenshot in Xcode.
  • 5
    Select the build
    Under Build, click + and select the build uploaded from Xcode.
  • 6
    Submit for review
    Click Add for Review → Submit to App Review. Average review time: 1–2 days. You'll receive an email when approved or rejected.

12. Pre-Submission Checklist

  • Bundle ID registered at developer.apple.com and set in Xcode
  • Apple Developer account active ($99 fee paid and confirmed)
  • Automatic signing enabled in Xcode with correct team selected
  • Info.plist has usage descriptions for ALL permissions used
  • Deployment target set (iOS 16.0 recommended)
  • App tested on at least one physical iPhone and the required simulators
  • No crashes on any required device size
  • All test/debug code removed
  • App icon created (1024×1024 px, no transparency, no rounded corners — Apple adds them)
  • Screenshots taken for all required device sizes
  • Privacy policy URL live and accessible
  • App Store Connect listing fully filled out (no empty fields)
  • Age rating questionnaire completed
  • If app requires login: test credentials provided in review notes
