1. The Problem — Cart Disappears on Restart

Right now, the cart lives only in memory — inside CartProvider._items. The moment the user closes the app (or the OS kills it), that list is gone. Next time they open the app, the cart is empty.

We already know how to persist simple values using SharedPreferences (Lecture 7). But SharedPreferences is a key-value store — it can save a single string or number against a name. It cannot save a list of structured objects cleanly.

SharedPreferences — not designed for lists

You would have to manually convert every cart item to a string, store each one separately, then parse them all back on startup. It becomes messy very quickly and breaks when the data has more than 2-3 fields.

SQLite — designed exactly for this

Store each cart item as a row in a table. To load all items: one query. To save one item: one insert. To delete one: one delete. Structured, fast, and scales to thousands of records.

2. What Is SQLite?

SQLite is a lightweight relational database that stores data in a single file on the device. It is not a server — there is no connection, no username, no password. It is just a file that your app reads and writes directly.

It is used by billions of apps worldwide — WhatsApp stores your messages in SQLite. Android's contacts app uses SQLite. iOS uses SQLite under Core Data. It is the most widely deployed database engine in the world.

Feature SharedPreferences SQLite
Best for Simple settings: one value per key Structured data: lists of objects with multiple fields
Data shape Key → Value Table → Rows → Columns
Querying No — just get by key Yes — filter, sort, search
Example use Auth token, dark mode, last username Cart items, messages, downloaded products, notes
Flutter package shared_preferences sqflite
Connecting to what you know: SQLite uses the same SQL you learned in your databases course — CREATE TABLE, INSERT, SELECT, UPDATE, DELETE. The only difference is that instead of running queries on a server, you run them on a file on the phone.

Why do we need the path package? The database is stored as a file on the device. The path package provides a join() function that correctly builds file paths on both Android (/data/data/app/databases/cart.db) and iOS (/Documents/cart.db) without you hardcoding the separator character.

5. Step 2 — Designing the Table

Before writing any code, we decide what our table looks like. A cart item needs:

Column Type Notes
product_id INTEGER Primary Key — uniquely identifies the product; prevents duplicates
title TEXT Product name — needed for display in the cart
price REAL Product price — needed for total calculation
thumbnail TEXT Image URL — needed for the product image in the cart
quantity INTEGER How many the user has added — this changes when +/- is tapped

In SQL, the CREATE TABLE statement looks like this:

CREATE TABLE cart_items (
  product_id  INTEGER PRIMARY KEY,
  title       TEXT    NOT NULL,
  price       REAL    NOT NULL,
  thumbnail   TEXT    NOT NULL,
  quantity    INTEGER NOT NULL DEFAULT 1
)
PRIMARY KEY means this column uniquely identifies each row. Because product_id is the PRIMARY KEY, the same product can never appear twice — the database enforces this automatically, which is exactly what we want.

6. Step 3 — Create CartDatabase

We follow the same pattern as the rest of the app: keep data logic separate from UI logic. Just like ProductService handles all API calls, CartDatabase handles all database calls. The provider just calls its methods.

6a — The Singleton Pattern

A database connection should be opened once and reused everywhere. Opening a new connection for every query wastes resources. We use the Singleton pattern — a design pattern that guarantees a class only ever has one instance.

lib/services/cart_database.dart — skeleton 
class CartDatabase {

  // The one and only instance — created once, never again
  static final CartDatabase instance = CartDatabase._internal();

  // Private constructor — no one outside this class can call "CartDatabase()"
  CartDatabase._internal();

  // The actual database — null until first use
  Database? _db;

  // Getter that opens the database the first time it is needed,
  // then returns the same open database every time after that.
  Future<Database> get database async {
    if (_db != null) return _db!; // already open
    _db = await _openDatabase();  // first time — open it
    return _db!;
  }
}
How to use a Singleton: Instead of CartDatabase() (which is blocked by the private constructor), you write CartDatabase.instance. This always gives you the same object.

6b — Opening the Database

lib/services/cart_database.dart — _openDatabase() 
import 'package:sqflite/sqflite.dart';
import 'package:path/path.dart';

Future<Database> _openDatabase() async {

  // Step 1: Find where the OS keeps databases on this device
  final dbPath = await getDatabasesPath();

  // Step 2: Build the full path to our file: ".../databases/cart.db"
  final path = join(dbPath, 'cart.db');

  // Step 3: Open (or create) the database file
  return openDatabase(
    path,
    version: 1,

    // onCreate only runs the very first time — when the file does not exist yet.
    // It creates the table. It never runs again on the same device.
    onCreate: (db, version) async {
      await db.execute('''
        CREATE TABLE cart_items (
          product_id  INTEGER PRIMARY KEY,
          title       TEXT    NOT NULL,
          price       REAL    NOT NULL,
          thumbnail   TEXT    NOT NULL,
          quantity    INTEGER NOT NULL DEFAULT 1
        )
      ''');
    },
  );
}

6c — The Four CRUD Methods

CRUD stands for Create, Read, Update, Delete — the four operations every database needs. Here is each one:

lib/services/cart_database.dart — CRUD methods 
// CREATE / UPDATE — insert a row, or replace it if product_id already exists
Future<void> insertOrUpdate(CartItem item) async {
  final db = await database;
  await db.insert(
    'cart_items',
    {
      'product_id': item.product.id,
      'title':      item.product.title,
      'price':      item.product.price,
      'thumbnail':  item.product.thumbnail,
      'quantity':   item.quantity,
    },
    // If a row with this product_id already exists, REPLACE it entirely.
    // This handles both insert (new product) and update (quantity changed).
    conflictAlgorithm: ConflictAlgorithm.replace,
  );
}

// READ — load all rows from the table
Future<List<CartItem>> getAllItems() async {
  final db   = await database;
  final rows = await db.query('cart_items'); // SELECT * FROM cart_items

  // Convert each raw Map (column → value) into a CartItem object
  return rows.map((row) {
    final product = Product(
      id:          row['product_id'] as int,
      title:       row['title']      as String,
      price:       row['price']      as double,
      thumbnail:   row['thumbnail']  as String,
      description: '', // not stored — not needed in cart
      category:    '',
      rating:      0.0,
    );
    return CartItem(product: product, quantity: row['quantity'] as int);
  }).toList();
}

// DELETE ONE — remove a single product by its id
Future<void> deleteItem(int productId) async {
  final db = await database;
  await db.delete(
    'cart_items',
    where:     'product_id = ?', // the ? is a placeholder — prevents SQL injection
    whereArgs: [productId],
  );
}

// DELETE ALL — wipe the entire table (checkout or logout)
Future<void> clearAll() async {
  final db = await database;
  await db.delete('cart_items'); // DELETE FROM cart_items
}
Always use the ? placeholder — never string concatenation. Writing where: 'product_id = $productId' is dangerous — a malicious value could break your query (SQL Injection). Writing where: 'product_id = ?' with whereArgs: [productId] is always safe.

7. Step 4 — Connect CartProvider to CartDatabase

CartProvider is already correct for managing in-memory state. We add two things:

  1. A _loadFromDatabase() call in the constructor — restores the cart on startup
  2. A database write after every state change — keeps the DB in sync
lib/providers/cart_provider.dart 
import 'package:flutter_application_2/services/cart_database.dart'; // NEW

class CartProvider extends ChangeNotifier {

  final List<CartItem> _items = [];
  final CartDatabase _db = CartDatabase.instance; // NEW

  // Constructor — load saved cart as soon as the provider is created
  CartProvider() {
    _loadFromDatabase(); // same pattern as ThemeProvider (Lecture 14)
  }

  // Reads all rows from SQLite and puts them in _items
  Future<void> _loadFromDatabase() async {
    final savedItems = await _db.getAllItems();
    if (savedItems.isNotEmpty) {
      _items.addAll(savedItems);
      notifyListeners(); // rebuild UI with restored cart
    }
  }

  // ── Add ──────────────────────────────────────────────────────
  void addProduct(Product product) {
    final index = _items.indexWhere((i) => i.product.id == product.id);

    if (index >= 0) {
      _items[index].quantity++;
    } else {
      _items.add(CartItem(product: product));
    }

    notifyListeners(); // UI updates immediately

    // Write the updated item to SQLite (no await — fire and forget)
    final updated = _items.firstWhere((i) => i.product.id == product.id);
    _db.insertOrUpdate(updated);
  }

  // ── Remove ───────────────────────────────────────────────────
  void removeProduct(int productId) {
    _items.removeWhere((i) => i.product.id == productId);
    notifyListeners();
    _db.deleteItem(productId); // delete from SQLite too
  }

  // ── Decrease ─────────────────────────────────────────────────
  void decreaseQuantity(int productId) {
    final index = _items.indexWhere((i) => i.product.id == productId);
    if (index < 0) return;

    if (_items[index].quantity > 1) {
      _items[index].quantity--;
      notifyListeners();
      _db.insertOrUpdate(_items[index]); // update quantity in SQLite
    } else {
      _items.removeAt(index);
      notifyListeners();
      _db.deleteItem(productId); // quantity is 0 — remove from SQLite
    }
  }

  // ── Clear ────────────────────────────────────────────────────
  void clearCart() {
    _items.clear();
    notifyListeners();
    _db.clearAll(); // wipe the entire table
  }
}
Notice the pattern: every method does the same two things in order — (1) update _items and call notifyListeners() so the UI responds instantly, then (2) call the database method without await so it saves in the background without making the user wait. The UI never freezes.

9. The Layered Architecture — Who Does What

This lecture is a good example of the three-layer architecture from Lecture 16:

Layer Class Responsibility
Presentation (UI) CartScreen Displays cart items; calls provider methods on button taps
Business Logic CartProvider Manages the in-memory list; decides add/remove/increase/decrease rules
Data CartDatabase Talks to SQLite; performs all CRUD operations; no UI knowledge

CartScreen never imports CartDatabase. CartDatabase never imports anything from Flutter UI. Each layer only talks to the layer directly below it.

10. Common Mistakes to Avoid

❌ Opening the database in every method

Future<void> insertItem(CartItem item) async {
  // Opens a brand new connection every call!
  final db = await openDatabase('cart.db', ...);
  await db.insert(...);
}

Opening a connection is slow. Doing it on every call wastes time and can cause corruption.

✅ Open once with the lazy getter

Future<void> insertItem(CartItem item) async {
  // Uses the cached connection
  final db = await database; // getter
  await db.insert(...);
}

The database getter opens the connection only on the first call, then reuses it every time.

❌ Awaiting the DB write before notifyListeners

void addProduct(Product p) async {
  _items.add(CartItem(product: p));
  await _db.insertOrUpdate(...); // waits...
  notifyListeners(); // UI only updates after DB write
}

The user taps Add to Cart and nothing happens for a brief moment while the DB write completes. Bad UX.

✅ notifyListeners first, DB write after

void addProduct(Product p) {
  _items.add(CartItem(product: p));
  notifyListeners();       // UI updates instantly ✅
  _db.insertOrUpdate(...); // no await — runs after
}

UI updates immediately. The database write happens in the background. The user sees instant feedback.

❌ Using string concatenation in WHERE

await db.delete(
  'cart_items',
  where: 'product_id = $productId', // ⚠️
);

SQL Injection risk — a crafted value could corrupt or expose your database.

✅ Always use ? placeholders

await db.delete(
  'cart_items',
  where: 'product_id = ?',   // ✅
  whereArgs: [productId],
);

sqflite escapes the value safely before running the query.

11. Quick Reference — sqflite Cheat Sheet

What You Want to Do sqflite Code
Get the databases folder path await getDatabasesPath()
Build a file path safely join(dbPath, 'myfile.db')
Open (or create) a database await openDatabase(path, version: 1, onCreate: ...)
Run a raw SQL statement await db.execute('CREATE TABLE ...')
Insert a row await db.insert('table', {'col': value, ...})
Insert or replace (upsert) await db.insert('table', map, conflictAlgorithm: ConflictAlgorithm.replace)
Read all rows await db.query('table')
Read rows with a condition await db.query('table', where: 'col = ?', whereArgs: [value])
Delete one row await db.delete('table', where: 'col = ?', whereArgs: [value])
Delete all rows await db.delete('table')
Get the singleton instance CartDatabase.instance

Key Takeaway: SQLite is the right tool whenever you need to store a list of objects that must survive app restarts. The pattern is always the same: a Singleton service class opens the database once and exposes clean CRUD methods; the Provider calls those methods after every state change and loads from them on startup; the UI never touches the database directly. This separation — UI talks to Provider, Provider talks to Database — is the architecture that keeps large apps maintainable.
