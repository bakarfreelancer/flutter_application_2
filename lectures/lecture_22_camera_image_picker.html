1. Two Image Sources

Every mobile app that lets users choose a photo must answer one question first: where does the photo come from? There are exactly two sources:

Camera — ImageSource.camera

Opens the device camera app. The user takes a new photo right now. The photo is saved to a temporary file and returned to your app.

Requires: CAMERA permission in AndroidManifest.

Gallery — ImageSource.gallery

Opens the device photo library. The user picks an existing photo. On Android 13+ this uses the system Photo Picker — no extra permission needed.

Requires: Nothing extra on modern Android.

2. The image_picker Package

image_picker is the official Flutter plugin for accessing the camera and photo library. It wraps the native camera/gallery UI so you do not have to write any platform-specific code yourself. 

# pubspec.yaml
dependencies:
  image_picker: ^1.1.2
# AndroidManifest.xml — add inside <manifest>
<uses-permission android:name="android.permission.CAMERA"/>

Key Classes

Class / TypeWhat it is
ImagePickerThe main class. Call .pickImage() on it.
ImageSourceAn enum: .camera or .gallery
XFileThe result. A cross-platform file wrapper. Use .path to get the file path string.
File (dart:io)Standard Dart file. Create from path: File(xFile.path). Needed for FileImage().
FileImageAn ImageProvider that loads from a local File. Used in backgroundImage.

3. Picking an Image — Step by Step

User taps avatar │ ▼ showModalBottomSheet ← choose Camera or Gallery │ ▼ ImagePicker().pickImage(source: ImageSource.camera / .gallery) │ ├── User cancels → returns null → do nothing │ └── User picks photo → returns XFile │ ▼ File(xFile.path) ← convert to dart:io File │ ├── setState(_profileImage = file) → UI updates immediately │ └── SharedPreferences.setString(path) → survives restart

Core picking function

Future<void> _pickImage(ImageSource source) async {
  // pickImage() opens the OS camera or gallery UI and waits for the user.
  // Returns null if the user cancels without picking anything.
  final XFile? picked = await ImagePicker().pickImage(
    source: source,
    imageQuality: 80,   // compress to 80% — smaller file, good enough for avatar
    maxWidth: 512,      // resize to 512px wide — no need for full resolution
  );

  if (picked == null) return; // user cancelled

  // Save path so the image loads again after a restart
  final prefs = await SharedPreferences.getInstance();
  await prefs.setString('profile_image_path', picked.path);

  // Update state — triggers a rebuild that shows the new photo
  setState(() => _profileImage = File(picked.path));
}
imageQuality: 80 and maxWidth: 512 are optional but recommended. A full-resolution camera photo can be 10–20 MB. Compressing it to 512px / 80% quality gives a file under 100 KB, which is more than enough for a small avatar circle.

4. Displaying a Local File Image

Flutter provides three common image widgets. The choice depends on where the image comes from:

Widget / ProviderSourceExample
Image.network()URL on the internetProduct thumbnails from API
Image.asset()Bundled in your app's assets folderLogo, placeholder images
Image.file() / FileImage()A file on the device's storageCamera photo, gallery pick ← our case

Using FileImage inside CircleAvatar

CircleAvatar(
  radius: 48,
  backgroundColor: primaryColor,

  // backgroundImage takes an ImageProvider, not a Widget.
  // FileImage wraps a dart:io File into an ImageProvider.
  backgroundImage: _profileImage != null
      ? FileImage(_profileImage!)   // show picked photo
      : null,                        // no image yet → show child instead

  // child is only shown when backgroundImage is null
  child: _profileImage == null
      ? Text(name[0].toUpperCase(), style: TextStyle(fontSize: 40))
      : null,
)
backgroundImage and child work together in CircleAvatar: when backgroundImage is set, it fills the circle and child is ignored. When it is null, child is shown instead. This makes the fallback-to-initials pattern very clean.

5. The Camera Badge Overlay (Stack)

We use a Stack to place a small camera icon on top of the avatar. This is a very common mobile UI pattern — you see it in WhatsApp, Instagram, etc. 

Stack(
  children: [
    CircleAvatar( ... ),   // the main avatar — layer 1 (bottom)

    // Camera badge — layer 2 (top)
    Positioned(
      bottom: 0,
      right: 0,
      child: Container(
        padding: const EdgeInsets.all(4),
        decoration: BoxDecoration(
          color: primaryColor,
          shape: BoxShape.circle,
          border: Border.all(color: scaffoldBg, width: 2), // white ring
        ),
        child: const Icon(Icons.camera_alt, size: 16, color: Colors.white),
      ),
    ),
  ],
)

Wrap the whole Stack in a GestureDetector with onTap: _showImageSourceSheet so tapping anywhere on the avatar opens the picker.

6. Bottom Sheet for Source Selection

A Modal Bottom Sheet slides up from the bottom of the screen — the standard mobile UI pattern for "choose one of a few options". We use showModalBottomSheet() which is built into Flutter. 

void _showImageSourceSheet() {
  showModalBottomSheet(
    context: context,
    shape: const RoundedRectangleBorder(
      borderRadius: BorderRadius.vertical(top: Radius.circular(16)),
    ),
    builder: (ctx) => Column(
      mainAxisSize: MainAxisSize.min, // sheet is only as tall as its content
      children: [
        ListTile(
          leading: const Icon(Icons.camera_alt),
          title: const Text('Take a Photo'),
          onTap: () {
            Navigator.pop(ctx); // close the sheet first
            _pickImage(ImageSource.camera);
          },
        ),
        ListTile(
          leading: const Icon(Icons.photo_library),
          title: const Text('Choose from Gallery'),
          onTap: () {
            Navigator.pop(ctx);
            _pickImage(ImageSource.gallery);
          },
        ),
      ],
    ),
  );
}
Always call Navigator.pop(ctx) to close the sheet before calling _pickImage(). If you open the camera while the sheet is still visible, the sheet will cover the camera UI on some devices.

7. Persisting the Image Across Restarts

The file itself is already saved on the device (by the camera or gallery system). All we need to remember is the path to that file. We save the path as a string in SharedPreferences — the same technique used in Lecture 14 for saving the dark mode preference.

First launch: _profileImage = null → show initials User picks photo: SharedPreferences.setString('profile_image_path', '/data/.../photo.jpg') _profileImage = File('/data/.../photo.jpg') → show photo App restarts: initState → _loadProfileImage() SharedPreferences.getString('profile_image_path') → '/data/.../photo.jpg' File(path).existsSync() == true → _profileImage = File(path) → show photo
// Save on pick
final prefs = await SharedPreferences.getInstance();
await prefs.setString('profile_image_path', picked.path);

// Load on startup
Future<void> _loadProfileImage() async {
  final prefs = await SharedPreferences.getInstance();
  final savedPath = prefs.getString('profile_image_path');

  // Always verify the file still exists before using it!
  // The file could be deleted by the OS to free storage.
  if (savedPath != null && File(savedPath).existsSync()) {
    setState(() => _profileImage = File(savedPath));
  }
}

9. Common Mistakes

MistakeFix
Not checking if picked == nullAlways null-check — user may cancel the picker
Using Image.file() in backgroundImagebackgroundImage needs an ImageProvider, not a Widget — use FileImage(file)
Saving the XFile path and never checking if the file existsCamera temp files can be deleted by the OS — call File(path).existsSync() before loading
Not calling Navigator.pop() before opening cameraClose the bottom sheet first, or the camera UI may appear behind it
Forgetting import 'dart:io'File lives in dart:io, not in Flutter — always import it explicitly
